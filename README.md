# Anki Voice

Spaced-repetition flashcards you can **listen to**, like a podcast. Cards are scheduled with **SM-2**, the Anki algorithm, and you can add them by voice.

## How a card plays

1. The question is read aloud, then a beep starts the think timer.
2. Press **play/pause** on your headphones, the lock screen or the big on-screen button as soon as you know the answer. How fast you press sets the SM-2 grade:

   | Press after the question ends | Grade |
   |---|---|
   | ≤ 2.5 s (or during the question) | 5 · Easy |
   | ≤ 5 s | 4 · Good |
   | ≤ 10 s | 3 · Hard |
   | no press | 1 · Didn't know |

3. The answer is read. If you pressed but got it wrong, press again during the answer or within 3 s after it. The card is then graded 2 (Wrong).
4. Cards graded below Good are repeated later in the same session until they stick. This is the SM-2 same-day rule, and these repeats don't reschedule the card.

**Signalling "I don't know"** is your choice in Settings:
- wait for the timer to run out
- double-press
- press the next-track button
- say "don't know" (experimental)

**Previous-track** repeats the question. All timings are adjustable in Settings.

## Features

- **Decks** for separate subjects. Start a session for one deck or for all of them.
- **Voice entry:** dictate each field, or use hands-free mode (the app asks "Question?", then "Answer?", and you say "save").
- **Progress:** day streak, reviews today, 30-day recall rate and a 7-day forecast of due cards.
- **Session summary:** recall rate, average recall time and a breakdown by grade. You can re-grade the previous card if the timing guessed wrong.
- **Practice mode:** listen to a deck when nothing is due, without changing its schedule.
- **Import and backup:** import Anki plain-text exports or `question ; answer` lines, and export a JSON backup.
- Light and dark themes.

## Stack

Expo SDK 57 / React Native 0.86 / TypeScript / expo-router. Android first; desktop comes later.

| Concern | Library |
|---|---|
| Text-to-speech | `expo-speech` (Android TextToSpeech) |
| Voice input | `expo-speech-recognition` |
| Storage | `expo-sqlite` |
| Headphone buttons, lock screen, background | local native module `modules/podcast-controls` (Kotlin) |

`modules/podcast-controls` is a foreground `mediaPlayback` service. It holds a `MediaSession` and streams silence, because Android only routes media buttons to the app that is currently playing audio. It reads raw key events, so press timing isn't delayed by Android's own double-click detection. It also provides native timers, because React Native pauses JS timers in the background, and it pauses the session when a phone call takes audio focus.

## Layout

```
src/core/          pure TS, no React Native imports (reusable on desktop)
  sm2.ts             SM-2 scheduling
  grading.ts         reaction time -> quality, voice phrase classification
  session.ts         podcast session state machine (reducer + effects)
  queue.ts, stats.ts, import.ts
src/session/runner.ts   runs the state machine's effects using the adapters below
src/adapters/speech.ts  TTS + speech recognition
src/data/db.ts          SQLite: decks, cards, review_log, settings (versioned migrations)
src/app/                screens (expo-router)
modules/podcast-controls/  native Android module
```

## Develop

Requirements:
- Node ≥ 20.19.4
- JDK 17+
- Android SDK (`ANDROID_HOME`)
- an Android phone with USB debugging, or an emulator

```bash
npm install
npm test             # core unit tests
npm run typecheck
npm run android      # expo run:android: builds the dev client and installs it
```

The app uses a custom native module, so it needs a development build and does **not** run in Expo Go. The `android/` directory is generated by `expo prebuild` and is git-ignored. Configure native behaviour in `app.json` or in `modules/`.

Importing from Anki: in Anki, use *File → Export → Notes in Plain Text*, then paste the result into *Cards → Import*. Lines in the form `question ; answer` also work.

## On-device test checklist

The native audio behaviour can only be verified on a real phone:

- [ ] 10+ cards with the screen locked: questions keep playing and timers fire
- [ ] Wired headset: a single press is graded by speed; double press works in "double" mode
- [ ] Bluetooth earbuds: play/pause, next and previous all arrive
- [ ] Lock-screen / notification buttons (Repeat, I know, Don't know, Stop)
- [ ] TTS does **not** trigger an audio-focus pause. If every question pauses the session, the TTS engine is taking focus; see `focusListener` in `PodcastService.kt`
- [ ] An incoming call mid-card pauses the session, which resumes after the call
- [ ] Hands-free card entry
- [ ] Kill and reopen the app: due dates are kept
